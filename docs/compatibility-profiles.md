# Compatibility profiles

Profiles are immutable runtime contracts. The initial profile pins Zingg `0.7.0`, DuckDB JDBC `1.5.5.1`, and Spark reference `3.5.5`, and records released semantics for timestamp-prefixed IDs, zero-scored transitive graph pairs, signed Java blocking hashes, and the registered similarities `exact`, `jaccard`, `normalized_levenshtein`, `jaro`, and `jaro_winkler`. The released `jaro_winkler` path delegates to Jaro. Classifier compatibility follows Spark's degree-3 polynomial exponent enumeration: terms are grouped by their highest-index input variable and its power, with lower-variable exponents enumerated inside each group. For two inputs and degree two, the order is `x0, x0², x1, x0·x1, x1²`. A semantic change requires a new profile ID rather than mutating an existing one.

An `ApplyLabelsRequest` may contain at most one decision for each ordered `(leftId, rightId)` pair. Duplicate pairs are rejected during request construction, before a provider can mutate its accepted-decision state; callers must resolve conflicting submissions explicitly rather than relying on rejection ordering.

The imported classifier support is deliberately envelope-specific: exactly three ordered stages—`VectorAssembler`, degree-3 `PolynomialExpansion`, and binary `LogisticRegressionModel`—with exact assembler→polynomial→classifier feature-column wiring. The direct checked-in fixture importer validates Spark 3.0.1 `PipelineModel` ordered `stageUids`; the isolated importer is built against Spark 3.5.5 and validates the runtime stage sequence and coefficient dimension. Both reject extra/reordered stages or disconnected feature columns before model publication, and serialize feature names through the strict JSON escaper. This does not claim support for arbitrary Spark ML pipelines or establish maintainer-approved v0.7 artifact provenance.
